## Unified "One Guildhall" service-wrapping decisions (November 16)

1. **Primary Command Center (Not an IDE Plugin):** Guildhall is the primary desktop workspace where the user chats with Council Members, inspects context budgets, reviews plans and diffs, and approves actions. External code editors (VS Code, Cursor, Visual Studio, JetBrains) are opened only when manually editing code; Guildhall never depends on proprietary VS Code/JetBrains UI extensions.
2. **Both Cloud Model APIs and Local CLI Agent Harnesses (Pillar 1 + Pillar 2):**
   - **Pillar 1 — Direct Cloud Model APIs:** Support stateless REST/SSE adapters for **Google Gemini API**, **Anthropic Claude API**, and **OpenAI API** using API keys stored in Windows DPAPI / Credential Manager, where `Guildhall.AgentHost` runs the entire prompt and MCP tool loop.
   - **Pillar 2 — Wrapped Local CLI Agent Harnesses:** Support spawning installed CLI coding agents (**Gemini CLI** via `gemini --acp` / `--output-format stream-json`, **Claude Code CLI** via `claude -p --output-format stream-json` / ACP, **OpenAI Codex CLI** via `codex exec --json` / `app-server`, and **Cursor Agent CLI** via `agent -p --output-format stream-json`) so the user can reuse existing Pro/Max/Google subscription logins and vendor agent harnesses inside Guildhall.
   - **SQL Source-of-Truth & Host Permission Invariant:** Even when a Council Member is backed by a wrapped CLI Harness, Guildhall's SQL Server database remains the canonical owner of transcripts, memory notes, and diffs. `Guildhall.AgentHost` injects SQL-owned context/memory into the harness and enforces Guildhall's permission modes (`Always ask`, `Ask for potentially unsafe actions`, `Unrestricted / autopilot`) rather than permitting unmediated `--yolo` execution.
3. **Backing Engine per Council Member:** Any Council Member (or individual session) can select a Local Model (Ollama), a Cloud Model API, or an External CLI Agent Harness as its backing brain.
4. **Cross-Member Conversation Reassignment ("Assign to guild member…"):** Users will be able to right-click a session and reassign or pass its context from one Council Member to another through an explicit handoff/edit mode (Phase 7). In Phase 1, this action is surfaced as an explicitly disabled/greyed-out menu item.
5. **Universal Planned-Feature Placeholder Rule:** Whenever a future-phase capability is requested for early UI visibility, record it in `docs/masterplan/` and render it in the UI as an explicitly disabled/greyed-out preview control that clearly states it is planned and never implies live connectivity.

## Architecture & System Design Passoff (November 16)

1. **Local Inference & Hardware Dynamics:**
   - **CPU vs. GPU Trade-offs:** For short conversational turns or smaller models, a modern CPU (such as the AMD Ryzen 7 9800X3D with its large L3 cache) paired with fast DDR5 memory handles inference smoothly without a drastic perceived drop in speed compared to a GPU, while keeping VRAM free for gaming and graphics work.
   - **Memory Bandwidth Wall:** Dedicated GPUs remain essential for sustained loads, long context windows, and heavier quantization tiers due to vastly superior raw memory bandwidth (hundreds of GB/s on GPU VRAM vs. tens of GB/s on system DDR5 RAM).
   - **Core Inference Concepts:** Explicit architectural accounting for **Inference** (applying learned weights to unseen input data), **Quantization** (compressing weights to lower precision to reduce VRAM/RAM footprints), **KV Cache** (storing key-value attention states from past tokens to accelerate subsequent generation), **Hallucination** (confident generation of fabricated outputs), and **Prompt Injection** (malicious/external inputs attempting to override system instructions).
2. **System Instructions & Context Management:**
   - **Static System Preambles:** Base instructions are configured as static `system` messages (or Modelfile parameters) in backend API calls rather than repeated across conversational turns.
   - **Context Preservation:** Conversational continuity is maintained by passing the historical message array of completed turns back to the model API per turn, supplemented by KV caching on warm/larger models and planned backend state compression.
   - **Modular Instruction Separation:** Separate **Tunable Parameters** (user/config-facing persona/role definitions, primary task objectives, and operational mode toggles such as reasoning effort) from **Global Guidelines** (system-wide operational boundaries instructing agents to rely strictly on tool outputs, respect workspace scope, and avoid fabricating system states or benchmark metrics).
3. **Caching & Persistence Architecture:**
   - **Canonical Storage vs. Runtime Memory:** Version-controlled **Markdown files** on disk serve as the source of truth for agent preambles and configurations (paired with immutable per-run snapshots in SQL `ChatRuns`). Compiled preambles and metadata are loaded at runtime into an in-memory store (`.NET ConcurrentDictionary` locally; Redis optional only for distributed scale) with a hard cap of **50–100 MB** to eliminate SQL/disk read bottlenecks per turn.
   - **Hot-Reloading Safety:** File watchers (`FileSystemWatcher`) invalidate and refresh the RAM cache when source Markdown files change. Reloading preambles affects only subsequent prompts and never wipes active conversations.
   - **Conversation State Persistence:** **SQL Server** (`GuildhallDev`) acts as the single source of truth for active conversation histories, ensuring durability across application restarts. Storing full active conversation histories in RAM is excluded from the MVP to avoid cache-sync complexity.
4. **Security & Backend Enforcement:**
   - **Hardcoded Backend Guardrails:** Never rely solely on prompt instructions for security. Enforce critical boundaries in the ASP.NET Core backend layer: strict read-only file access defaults, prevention of credential or sensitive data exfiltration, and mandatory human-in-the-loop approval gates for any destructive or mutating system operations.
   - **Process Isolation:** Maintain strict isolation between the Tauri UI frontend and the ASP.NET Core agent host backend so prompt injections cannot escalate to local OS compromise.
5. **Multi-Tier Resilience & Missing State Tracking:**
   - **Multi-Layer Health Checks:** Implement health checks, bounded auto-retry logic, and graceful degradation across all five architectural tiers: (1) **Tauri UI process**, (2) **ASP.NET Core Agent Host** (central orchestrator managing agent lifecycles, reasoning loops, and tool bindings), (3) **SQL Server database**, (4) **Ollama inference service** (handling crashes, OOM limits, and post-update restart failures), and (5) **Active MCP tool servers**.
   - **Additional State Tracking:** Track **Tool Execution Rollbacks** (transactional/compensating rollback mechanisms for failed tool actions), **VRAM Residency Tracking** (monitoring which models are currently loaded in VRAM via `/api/ps` to prevent cold-swap latency stalls), **Cross-Turn Budgets** (cumulative token usage and reasoning effort limits across multi-turn sessions), and **Delegation Dependency Graphs** (execution graphs when multiple Council Members or sub-agents delegate tasks to one another).

## Connection versus agent selection

The UI may show local, cloud API, and CLI harness choices before they are connected. Selecting an option is not the same as authenticating it. A local Ollama model needs no hosted account. A cloud API or CLI harness requires its supported API key or CLI sign-in flow before it can run; Guildhall should not require a GitHub account to select a local project or a cloud account to use local chat.

## Review and acceptance gates

- Every provider/harness/service card has explicit `Not connected`, `Connected`, `Unavailable`, `Needs sign-in`, or `Planned` status and a tested connect/disconnect/reconnect path before its phase is complete.
- Five-tier health checks (Tauri UI, ASP.NET Core Host, SQL Server, Ollama, and MCP tool servers) recover cleanly from simulated daemon crashes, OOM limits, or unavailable dependencies without crashing the app or duplicating runs.
- Markdown preamble hot-reloading refreshes the bounded `.NET ConcurrentDictionary` cache (`50–100 MB` cap) on file changes and affects only subsequent runs while preserving active conversations in SQL Server.
- Project selection works with a local non-Git folder and a local Git repository while offline. GitHub is an optional route, not the local-project picker.
- Hardcoded ASP.NET Core backend guardrails (read-only defaults, anti-exfiltration, human-in-the-loop approval gates, and tool execution rollbacks) and access modes are tested with the same action matrix across both native MCP tools and wrapped CLI harnesses so labels match enforced behavior. Full autopilot is visibly dangerous and scoped to the active project and selected connections.
- Usage totals, VRAM residency indicators, and cross-turn budgets identify provider/harness, measurement source, currency/time range when applicable, and missing data without fabricating metrics.
- Pane collapse, app zoom (`Ctrl`/`Cmd` `+`, `-`, `0`), focus restoration, and narrow-window access pass functional QC.
