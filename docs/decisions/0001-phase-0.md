# Phase 0 decisions

Status: all nine presented design choices are accepted. The user subsequently authorized building Phase 0 and explicitly approved the concrete SQL, Node, and Ollama setup actions. Phase 0 is locally implemented and verified; see `docs/masterplan/phase 0/verification.md`.

## Accepted November 15, 2026

1. **Backend structure:** one ASP.NET Core host project with internal modules. Extract libraries when a demonstrated consumer or boundary requires them.
2. **Persistence:** SQL Server accessed through EF Core, using EF Core migration tooling. No custom migration engine.
3. **Desktop transport:** React calls the host directly over authenticated loopback HTTP. A narrow Tauri command supplies session bootstrap configuration. Review token handling, origin restrictions, and native permissions before implementation.
4. **SQL Server target:** use the existing default local instance (`localhost`, service `MSSQLSERVER`) for the dedicated `GuildhallDev` application database. Provisioning was separately approved and completed.
5. **Database permissions:** use separate runtime and migration identities. Runtime must not be able to change schemas; verify this against SQL Server.
6. **Development lifecycle:** one launcher owns host and desktop processes, waits for authenticated health, and cleans up only its own processes. It does not manage SQL Server or Ollama services.
7. **Local SQL certificate policy:** retain encrypted transport and explicitly allow the untrusted certificate only for the selected local development instance. Do not change machine trust or SQL Server settings. Remote connections still require certificate validation.
8. **Database authentication:** dedicated restricted SQL login for the running host; existing Windows identity for explicit migrations. Runtime credentials must be OS-protected and never passed to desktop processes. Review actual grants and provisioning before execution.
9. **Node toolchain:** upgrade the system-selected Node version rather than use a project-local portable distribution. nvm-windows was already installed at `C:/Users/isagn/AppData/Roaming/nvm/nvm.exe`. The separately approved switch is complete: `C:/Program Files/nodejs` now points to its `v24.13.0` directory. No nvm reinstallation or Node download was needed.
