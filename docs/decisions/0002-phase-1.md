# Phase 1 decisions

Status: planning only. The user requested a plan, not implementation, database changes, installations, or model downloads. Phase 0 remains the running application.

## Product choices accepted November 15, 2026

1. **Agent configuration:** one Local Assistant with editable instructions and model selection. No multiple-agent management screen.
2. **Model switching:** allow changing models within a conversation for future replies. Preserve history and record the model and instructions used for each run.
3. **Model selection:** build deterministic chat behavior first; select a useful model at the live-testing checkpoint, with separate approval for any download. The installed `smollm2:135m` is a plumbing fixture, not a quality baseline.

## Engineering defaults proposed for plan review

- Keep the existing host/desktop/test projects and SQL Server instance. Use the existing EF Core, HttpClient, React state, and fetch APIs; add no orchestration, state-management, queue, or provider SDK framework.
- One active generation across the local host; reject another send as busy. No queue or independent background work.
- Start a run with authenticated POST; observe it with authenticated fetch consuming SSE. Never move bearer tokens into URLs to accommodate EventSource.
- Stream committed assistant-text snapshots with increasing run revisions. Checkpoint text in bounded batches; SSE reads the latest committed state. No durable per-token event table, replay service, or pub/sub infrastructure.
- Preserve cancelled, failed, and interrupted partial replies with explicit status. Exclude incomplete turns from future model context. Never automatically resume/retry inference after a host restart.
- Keep the full transcript. Initially reject context beyond conservative configured limits rather than silently truncate, summarize, or delete history.
- Plain-text chat rendering and versioned JSON export. Rich Markdown, attachments, search, deletion, import, and tool use remain deferred.
- Prepare reviewed additive migrations and table-specific runtime DML grants. Preserve the separation between Windows migration identity and restricted SQL runtime login.
- Verify SQL backup/restore before meaningful chat data accumulates. Export is an additional portability path, not a substitute for restore testing.

These engineering defaults are specified in `../phase-1-contracts.md` and broken into tasks in `../phase-1.md`. They are reviewable recommendations, not additional approvals already obtained from the user.
